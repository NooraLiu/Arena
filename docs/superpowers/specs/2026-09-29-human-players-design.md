# 人类玩家加入 Arena 对局 — 设计

日期:2026-09-29

## 目标

让人类在网页上占一个(或多个)座位,和 `arena-player` agent 同桌玩一整局。

- 现在:用户一人 + 5 个 AI 座位,AI 座位仍由聊天里的 Claude 驱动(叫 agent 写决策文件)。
- 以后:多个人类座位;以及全是人类、不需要 Claude 在场的对局。
- 成功标准:用户在 `/play.html` 上只看到自己座位本该知道的信息,能完成移动、行动、附加行动、喊话、备忘和出局感悟,整局无需在聊天里手动转述决定。

## 不做的事

- 不改引擎和结算规则;人类座位只是"换一种方式交决策文件"。
- 不做账号、房间大厅、跨网络部署。局域网访问只留开关,默认只听本机。
- 不让服务端调用 Claude API;有 AI 座位时仍由聊天里的 Claude 推进。

## 整体结构

```
浏览器 /play.html?seat=N&key=K  ⇄  app/server.py  ⇄  play/live/ 下的文件  ⇄  Claude(聊天里推进)
```

现有流程不变:`plan` 写每个被问座位的提示 → 各座位写 `play/live/decisions/sN.json` → `movephase` / `actphase` 结算 → `endround` → `startround`。人类座位与 AI 座位唯一的区别是决策文件由服务端写,而不是 agent 写。

### 存档里新增的状态(`eng` 上)

- `eng.humans: dict[int, str]` —— 人类座位 → 随机口令(`secrets.token_urlsafe(8)`)。
- `eng.phase: str` —— 当前等待的阶段:`"move"` / `"act"` / `"reflect"` / `"over"`,由 `plan` 与 `endround` 维护,供视图和服务端判断现在该交什么。

### 开局

`session.py init --players 6 --seed S --human 1`(随机 1 个人类座位)或 `--human 2,4`(指定座位)。`init` 打印每个人类座位的玩家链接 `http://localhost:8000/play.html?seat=N&key=K`。

### 人类座位视图 `play/live/human/sN.json`

`plan`(以及 `endround` 为出局者生成感悟提示时)对每个人类座位写一份 JSON,只含该座位本该知道的信息:

- `round`、`phase`、`waiting`(是否轮到本座位)、`submitted`(本步是否已交)。
- 公开场况:开放区、各区剩余张数、盛宴/沙尘暴、每个座位的角色名、公开血量、公开位置(第 1 回合移动阶段为未知)、装备武器、是否存活。
- 本座位私密:角色数值与技能、手牌(含牌 ID)、秘密身份与胜利条件、`【身份进度】`、Lovers 的恋人、Iris 已偷看到的身份、已声明内容、上回合备忘。
- 消息:公开喊话 + 发给本座位/本座位发出的私聊;最近的公开事件。
- 本步合法选项(由服务端/`session` 计算,页面只做展示):可攻击座位、是否在中心被迫攻击、可用附加行动(带可选参数:同区座位、手牌 ID、可炸区)、下回合可去的区、是否可声明身份。
- 开局简报全文(规则 + 角色 + 身份 + 打法倾向),页面放在可折叠面板里。
- 游戏结束时:结果(`result` 的内容)与观战页链接。

视图由新函数 `session.human_view(eng, seat) -> dict` 生成;它复用 `_prompt` 已有的取数逻辑(`_extras`、`_next_legal`、`_legal_zones`、`build_observation`、`_progress`),不重复规则判断。

### 提交决策

`POST /api/decision?seat=N&key=K`,body 与 agent 的决策 JSON 相同(`action` / `extra` / `move` / `say` / `memo`;感悟阶段为 `reflection`)。服务端:

1. 口令不符 → 403。
2. 不是本座位该交的阶段(未被问、已出局且非感悟阶段、游戏结束)→ 409。
3. 用新函数 `session.validate_decision(eng, seat, phase, d) -> list[str]` 校验:攻击目标必须在可攻击列表;中心被迫攻击时主行动不能是抽牌;移动必须在可去列表;附加行动必须在可用列表且参数合法(座位同区、牌 ID 在手里);喊话最多 2 条、对象为 `all` 或存活座位。有错 → 400 并返回错误列表,不写文件。
4. 合法 → 写 `play/live/decisions/sN.json`(与 agent 同格式),本步结算前允许重复提交覆盖。

`GET /api/view?seat=N&key=K` 返回该座位视图;口令不符 → 403。服务端不直接暴露 `play/live/human/` 目录。

### 推进:`advance()`

把现在手动敲的一串命令抽成 `session.advance() -> dict`:

- 读当前 `eng.phase`,检查被问座位的决策是否到齐;缺谁就返回 `{"waiting": [座位...]}` 不动。
- 到齐则执行该阶段结算(`movephase` / `actphase` + `endround` + `startround` + 下一步 `plan`),循环直到遇到需要有人回答的一步或游戏结束;返回 `{"asked": [...], "reflect": [...], "over": bool}`。
- 感悟阶段:出局者交感悟后照常收集(`_absorb_reflections`),不阻塞下一回合开始,但人类出局者的感悟框一直可提交直到游戏结束。

谁来调用 `advance()`:

- **有 AI 座位**:Claude 在聊天里调用;对 `asked` 中的 AI 座位叫 agent,对人类座位用后台监听等待其决策文件出现,然后再调 `advance()`。
- **全是人类**:服务端每收到一份合法决策后调用一次 `advance()`,无需 Claude。

现有的 `plan` / `movephase` / `actphase` / `endround` 命令保留,`advance()` 内部调用它们的函数体,不改其行为。

### 页面 `app/play.html`

沿用观战页样式与地图画法,每 2 秒拉取一次 `/api/view`:

1. 顶栏:回合、阶段、状态("轮到你了" / "已提交,等待其他人" / "等待其他人")、开放区与剩余张数、盛宴/沙尘暴。
2. 地图:五个区,公开位置、血量、装备武器;第 1 回合移动阶段位置显示为未知。
3. 我的面板:角色、血量、攻击、技能;手牌;身份、胜利条件、身份进度;私下知道的信息。
4. 消息区:公开喊话、私聊、最近公开事件。
5. 决策表单(仅在轮到时出现):主行动(抽牌 / 攻击下拉)、附加行动(按可用列表生成控件)、下回合去向、最多 2 条喊话(公开或私聊某座位)、备忘;提交后锁定并显示已提交,本步结算前可"修改"。服务端返回的校验错误显示在表单上方。
6. 出局后:感悟输入框(提交后只读),其余变为只读的公开信息;游戏结束显示结果与观战页链接。
7. 可折叠"规则"面板:开局简报全文。

### 信息隐藏

- 视图只由 `human_view` 生成,测试保证其中不出现其他座位的身份、手牌、私聊、备忘与思考。
- 观战页(`/`、`/live/game.json`)仍是上帝视角;人类对局进行中,Claude 在聊天里只报告公开事件与"等待你提交",不贴身份、手牌、agent 备忘。
- 默认只监听 `127.0.0.1`;`ARENA_HOST=0.0.0.0` 时才开放局域网。

## 出错与恢复

- 服务端或页面重启不影响对局:状态全在存档与 `play/live/` 文件中,刷新即恢复。
- 决策文件已存在但格式坏:沿用 `_load_decisions` 的容错(按默认处理并提示)。
- `ARENA_SANDBOX` 沙盒路径对视图与决策同样生效,测试不碰真实对局。

## 测试

- `human_view`:6 个座位各生成一份,断言不含其他座位的身份名、手牌 ID、私聊内容;第 1 回合移动阶段不含他人位置;含本座位身份进度。
- `validate_decision`:不同区攻击、中心选抽牌、不相邻移动、不在手里的牌 ID、非同区交换、超过 2 条喊话、对已出局座位私聊 —— 均被拒;合法决策通过。
- `advance()`:沙盒里 5 个固定 AI 决策 + 1 个人类决策文件,反复调用能推进到游戏结束;缺人类决策时返回 `waiting`。
- 服务端:错误口令 403;非本阶段 409;合法提交写出与 agent 同格式的文件;全人类对局中最后一份决策到达后自动推进。
- 页面:在内置浏览器里以人类座位完整走一回合(移动、行动、附加行动、喊话),截图确认。
